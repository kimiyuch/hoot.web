- **The thread** (2026-11-06, step 4 of [`docs/SOCIAL.md`](docs/SOCIAL.md)): table `activities` (`user_id`, `type`, `data` JSON, timestamps; sorted by `updated_at`, the last change). Types: `followed` (a show/movie), `favourited`, `started` (Watching), `finished` (Watched; "watched" for movies), `rated`, `followed_user`. Written only by `App\Services\Activities`, called from `Library` and `Network`. Calm rules: `followed`, `favourited` and `followed_user` collapse into the latest entry of that type within 10 minutes (`Activities::WINDOW`); undoing within the window (unfollow, unfavourite, another status, clearing a rating, unfollowing a person, removing a follower) takes the item back without moving the entry; a rating right after finishing goes on the "finished" entry; re-rating within the window replaces it; unfollows are never news; no backfill; blocking removes "followed" mentions between the two for good. Each show or movie in it has a Follow button (`LibraryActions` with `:with-heart="false" :with-status="false"`): inline next to the time when the entry is about one, under a "Show all N" toggle listing each one when it's several. Shown as **From people you follow** in For you's sidebar (and under the empty state), only once you follow someone: Livewire `Thread`, 8 at a time with "Load more" (it grows a limit rather than a real cursor, which is fine at this size). Only accepted follows, nobody across a block, and "followed X" only where you may see X (private accounts you don't follow are left out; yourself is "you"), with their current name.

- **Favourites** (2026-11-06, step 0 of [`docs/SOCIAL.md`](docs/SOCIAL.md)): a row in `show_user` / `movie_user` is now "in your library", with a `following` flag and a `favourite_position` (null or 1–10). `User::shows()`/`movies()` are the followed ones, `libraryShows()`/`libraryMovies()` all rows, `favouriteShows()`/`favouriteMovies()` in order. Settings → Favourites lists them with up/down and remove (`App\Livewire\FavouritesList`). Max 10 shows and 10 movies (`Library::MAX_FAVOURITES`).
- **Episode search link** (2026-11-06, Settings → Extras): `users.episode_search_url`, a URL you set yourself with `{query}` in it (validated: http(s), has the placeholder). Set, a small grey chain icon (`components/episode-search-link`, tooltip "Search on host") sits next to episodes that are out, in the timeline (after the episode name, so the right side stays the time and the service) and in Following's episode lists (after the date, in a fixed slot). `App\Services\EpisodeSearch` builds the query: "ted lasso s04e03", a season dropping at once "night shift s02", specials just the show; punctuation dropped. Hoot ships no destination on purpose (the user wanted Pirate Bay links; a built-in link or a redirect service were rejected as the same legal exposure); the user puts their own URL in their account.

Discover's premieres drop hidden ones before the service counts; Any time adds `without_keywords=210024` (TMDB's anime keyword) and, since TMDB can't exclude a language, goes through `Browse::merge`, the same merge as All regions, which skips hidden titles and still cuts pages of 20 (at most `3 × page + 5` TMDB pages per country, in case nearly everything is hidden). Merged pages show "Page 3" without "of N". A quiet "Hiding anime, Korean and Indian titles. Change" line sits under Discover's intro. Search, For you, profiles and the thread still show everything. In the data export.

## Decisions

- Accounts since 2026-11-06 (before, there was no login). Pages are `noindex` except the landing page. Mail goes to MailHog locally (`127.0.0.1:1025`, inbox at http://127.0.0.1:8025); mails use the published, restyled templates in `resources/views/vendor/{mail,notifications}`, with the wording in `AppServiceProvider`. The server needs a real mailer in `.env` for verification and reset mails.
- The pages are Blade with a little vanilla JS, not Inertia. Since 2026-11-06 the interactive bits are **Livewire 4 islands** (not full-page components, and not htmx, which the user ruled out): `LibraryActions` (the heart and Follow on every card and in For you's Following), `FavouritesList` (Settings) and `SearchPanel` (inside the ⌘K dialog; the `<dialog>` stays plain Blade so Livewire's morphing doesn't close it) and `DiscoverPage` (the whole Discover page: filters and pages apply in place, the URL follows via `#[Url]`, the links keep real hrefs; the drawer and "Show more" have `wire:ignore.self` so they stay open). Also `PersonActions` (follow, request, accept, block), `UpcomingDays` (the timeline) and `Thread` (From people you follow, with small Follow buttons via `LibraryActions`' `small`, `with-heart` and `with-status` flags). They change in place and send a `toast` browser event, which app.js shows with `#toast-template`. Unfollow in For you and the Settings forms still post and reload normally. Use Livewire for the social features too (follow buttons, status menu, thread "Load more").
- Tailwind 4 dropped the pointer cursor on buttons; one rule in `resources/css/app.css` (`@layer base`) gives it back to buttons, `summary`, checkboxes, radios and selects, so no `cursor-pointer` classes are needed.
- TV comes only from TVmaze. Movies come from TMDB.
- There's no region filter for release dates (the earliest release anywhere counts). Browse does need a country for its service filter, because TMDB only knows availability per country. TMDB ignores `with_watch_providers` without `watch_region`, so *All regions* merges the countries in `hoot.regions`, not all 139 TMDB regions. TMDB's own order isn't strictly by the popularity it returns (its sort index lags), on a single country too; the merge keeps TMDB's order.
- Premieres only cover shows that premiered in the last 30 days. Past regular-TV premieres only come from the US and UK. Streaming premieres are covered worldwide.

## On another machine

The repo doesn't carry `.env` or the SQLite database. After cloning:

```sh
git clone https://github.com/kimiyuch/hoot.web.git ~/Jamon.digital/Webroot/hoot.web
cd ~/Jamon.digital/Webroot/hoot.web
composer install && npm install
cp .env.example .env && php artisan key:generate   # then copy TMDB_TOKEN from the old machine's .env
touch database/database.sqlite && php artisan migrate
npm run build
herd secure hoot.web                                 # if Webroot is parked in Herd; otherwise: herd link hoot.web
php artisan hoot:refresh                             # about 70 s
```

The local test user (`test@possum.local`) only exists in the old machine's database: sign up again (mail goes to MailHog, if it runs there) or create one with `php artisan tinker`. If you copy `database/database.sqlite` over from the other machine instead, run `php artisan migrate` afterwards; accounts without a username then land on `/choose-username` first.
